# 한국외대 논문 양식 hwpx 작성 스킬

사용자가 "<프로젝트 이름> 프로젝트로 <주제> 논문 초안 써줘"라고 하면:
원고 작성 → JSON으로 저장 → `scripts/make_hwpx.py`로 hwpx 생성 →
`<내 드라이브>\논문작업실\<프로젝트 이름>\AI 작성글\YYYY-MM-DD_제목.hwpx`에 저장.

## 1. 프로젝트 확인

- `data/projects.json`(앱 저장 파일)에서 프로젝트 이름을 찾는다. 이름은 정확히 일치해야 한다.
- 없으면 만들지 말고, 앱의 프로젝트 화면에서 먼저 만들라고 안내한 뒤 멈춘다.
- 드라이브 폴더가 "실패" 상태면 앱에서 "다시 시도"를 누르라고 안내한다.

## 2. 양식 (assets/template.hwpx = 사용자가 준 `논문양식.hwpx` 사본)

스크립트는 양식 파일의 글꼴·크기·여백·스타일·쪽 번호를 **그대로** 쓰고, 양식 속 문단을 복제해
내용만 바꾼다. 서식을 바꾸고 싶으면 이 파일을 한글에서 고친 뒤 같은 이름으로 덮어쓰면 된다
(스타일 이름·번호는 유지할 것: 35 제목, 37 이름, 38 목차, 43/44/45 장·절·목, 39 본문, 42 예문,
49 참고문헌 제목, 50 참고문헌 항목).

**구성 순서 (고정)**: 제목 → 이름(＊각주: 소속) → 목차(표) → 본문(1. / 1.1. / 1.1.1) → 참고문헌(새 쪽)
- 용지 A4, 한컴바탕, 제목 14pt, 장 13pt, 절 11pt, 목·본문 10pt, 각주·예문·참고문헌 9pt (양식 값)
- 국문초록·영문초록·표지는 이 양식에 없으므로 만들지 않는다.

## 3. 원고 쓰기

요청에 없는 정보는 묻지 말고 기본값을 쓰고, 마지막에 바꿀 수 있다고 알린다.
- 이름: git `user.name`, 소속 각주: "한국외국어대학교 대학원 ○○학과 석사과정"
- 분량: 정하지 않으면 장 3~5개, 각 절 2~4문단의 "초안" 분량

**문체**: 학위논문 문어체 "~이다", "~하였다". 구어체·존댓말·"저는" 금지. 1인칭은 "본 연구", "연구자".

**번호 체계** (스크립트가 자동으로 붙임 — 원고에는 번호 없이 제목만):
장 `1.` → 절 `1.1.` → 목 `1.1.1` / 예문 `(1) a. b.`(문서 전체 일련번호) / 표 `<표 1>`(일련번호)
- 본문에서 예문·표를 가리킬 때는 번호를 직접 쓴다: "예문 (1a)는…", "<표 1>과 같이…" (순서대로 1, 2, 3…)

**각주**: 본문 문장 안에 `[^각주 내용]`을 쓰면 그 자리에 각주가 달린다. 출처 인용은 각주로
`[^저자(연도:쪽) 참고.]` 형식. 각주 번호는 이름 각주(＊)가 1번을 쓰므로 본문은 2번부터 매겨진다(양식과 동일).

**참고문헌**: 한 목록에 국문 → 중문·일문 → 영문 순. 형식은 양식 예시를 따른다.
- 논문: `저자(연도), 「논문 제목」, 『학술지명』제00권`
- 책: `저자(연도), 『책 제목』, 출판지: 출판사` / 번역서: `원저자 저, 역자 역(연도), 『제목』, 출판지: 출판사`
- 같은 저자 반복: `----(연도), …` / 영문: `Bloomfield, L.(1933), Language. London: George Allen & Unwin.`

**정직성 규칙 (중요)**
- 실재하는지 확신할 수 없는 문헌은 절대 지어내지 않는다. 확실한 고전 문헌만 쓰고, 나머지는
  `[확인 필요] 저자명(연도), 「(예시) 제목」, 『학술지명』제00권` 형식의 자리 표시로 둔다.
- 사용자가 실제 데이터를 주지 않았으면 결과·수치·표 내용 앞에 `[예시 결과 — 실제 자료로 교체]`를 붙인다.

## 4. 원고 JSON 형식

전체 예시는 `references/sample-manuscript.json`. 원고는 임시 폴더(예: `$env:TEMP\thesis-manuscript.json`)에 UTF-8로 저장한다.

```json
{
  "title": "논문 제목", "author": "이름", "author_note": "한국외국어대학교 대학원 ○○학과 석사과정",
  "chapters": [
    { "title": "서론",
      "blocks": ["장 바로 아래 문단 (각주는 [^내용])"],
      "sections": [
        { "title": "절 제목",
          "blocks": [
            "문단",
            { "example": ["예문 a", "예문 b"] },
            { "table": { "caption": "표 제목", "rows": [["머리1", "머리2"], ["값1", "값2"]] } }
          ],
          "subsections": [ { "title": "목 제목", "blocks": ["문단"] } ] }
      ] }
  ],
  "references": ["국문 문헌", "中文文献", "English reference"]
}
```

- `blocks` 안에는 문단(문자열), 예문(`example`: 한 개면 `(1) 예문`, 여러 개면 `(1) a. … b. …`), 표(`table`: 첫 행이 머리 행)를 섞어 쓴다.
- 장은 최소 2개(서론, 결론).

## 5. hwpx 만들기

```powershell
python .claude/skills/hufs-thesis-hwpx/scripts/make_hwpx.py "$env:TEMP\thesis-manuscript.json" --project "프로젝트 이름"
```

- `python`이 안 되면(Windows 스토어 안내가 뜨면) 전체 경로를 쓴다:
  `& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" ...`
- 필요 라이브러리: `python -m pip install python-hwpx` (설치됨, 6.8.0 — 검증용, lxml 포함)
- 스크립트가 하는 일: 양식 복제로 문서 생성 → 저장 → 다시 열어 패키지·스키마·내용 검사.
  마지막 줄 `저장 완료: <경로>`를 확인한다. 양식 파일 자체에 있는 스키마 경고 2종(한글이 정상으로 여는 것)은 무시한다.
- 같은 이름 파일이 있으면 덮어쓰지 않고 `_2`, `_3`을 붙인다. 프로젝트 폴더 밖에는 아무것도 쓰지 않는다.
- 테스트용으로 드라이브 대신 아무 경로에 만들려면 `--project` 대신 `--out 경로.hwpx`.

끝나면 사용자에게 저장 경로, 장 구성, `[확인 필요]`/예시 표시가 있는 곳을 짧게 알려준다.
앱의 프로젝트 화면을 새로고침하면 "AI 작성글" 칸의 개수가 늘어난다.

## 6. 참고·한계

- 학교 내규: 한국외대 일반대학원 「학위논문 작성 내규」(https://gra.hufs.ac.kr/gra/6530/subview.do).
  2026-10-22부터 서식은 내규 대신 사용자가 준 양식 파일을 기준으로 한다.
- 목차는 양식처럼 장 제목만 넣고 쪽 번호는 없다.
- 줄 배치 정보는 비워 두어 한글이 열 때 다시 계산한다(첫 열기에 잠깐 걸릴 수 있음).
- 그림, 각주 안의 서식(기울임 등)은 아직 지원하지 않는다. 제출 전 반드시 학교 양식과 대조할 것.
